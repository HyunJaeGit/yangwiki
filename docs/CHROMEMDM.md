디벗 크롬북 MDM 및 양품화 안내서
작성 기준: 2026년 11월 24일
대상: Google Workspace for Education / Chrome Education Upgrade(CEU)로 관리하는 학교 크롬북

============================================================
1. 문서 목적
============================================================

이 문서는 학교에서 학생용 크롬북을 Google 관리 콘솔로 관리하는 기본 구조와, 수리·초기화·재배정 시 필요한 파워워시 허용 및 재등록 과정을 정리합니다.

여기서 말하는 양품화는 기기를 초기화하고, 기기 상태를 점검한 뒤, 학교에서 다시 사용할 수 있도록 관리 상태와 정책을 확인하는 작업을 뜻합니다. 학교의 실제 자산·수리 절차와 관리자 권한 범위가 우선입니다.

============================================================
2. Google 관리 콘솔과 MDM 개념
============================================================

Google 관리 콘솔(admin.google.com)은 학교 계정과 ChromeOS 기기의 설정을 관리하는 웹 콘솔입니다. 학교가 크롬북을 관리 콘솔에 등록하면 관리자는 조직 단위(OU)별로 기기 정책을 적용할 수 있습니다.

CEU(Chrome Education Upgrade)는 ChromeOS 기기에 학교용 관리 기능을 제공하는 업그레이드입니다. 첨부된 「디벗 MDM(크롬-CEU)」 자료에 따르면 등록된 기기는 관리 콘솔에서 '프로비저닝됨'으로 표시되고, 조직 단위에 배치하여 정책과 기기 상태를 관리합니다.

대표적으로 관리할 수 있는 항목:
- 앱·확장 프로그램의 강제 설치, 허용, 차단
- Google Play 및 Chrome 웹 스토어 이용
- Wi-Fi, VPN 등 네트워크 설정
- 게스트 모드 및 로그인 계정 제한
- 자동 업데이트와 기기 사용 시간
- URL 접근 제한
- 파워워시 허용 여부
- 초기화 후 강제 재등록
- 분실 기기 사용 중지 및 반환 안내

중요한 구분:
- 사용자 계정 정책은 학생 계정이 로그인하는 곳에 적용될 수 있습니다.
- 기기 정책은 해당 크롬북이 학교 관리 도메인에 등록되어 있어야 적용됩니다.
- 학생 계정으로 로그인한 사실만으로 기기 전체가 학교 MDM에 등록되는 것은 아닙니다.

============================================================
3. 양품화 전 확인 사항
============================================================

초기화를 시작하기 전에 아래를 확인합니다.

[ ] 대상 기기의 자산번호와 일련번호(SN)를 확인한다.
[ ] 관리 콘솔에서 해당 SN의 기기를 찾는다.
[ ] 현재 상태가 프로비저닝됨/등록됨, 사용 중지됨, 등록 해제됨 중 무엇인지 확인한다.
[ ] 기기의 조직 단위(OU)를 확인한다.
[ ] 기기를 학교에서 다시 사용할지, 수리 반송·폐기·양도 등으로 관리에서 제외할지 결정한다.
[ ] 필요한 로컬 데이터가 있는 경우 백업했는지 확인한다.
[ ] 파워워시 허용 정책 및 초기화 후 재등록 정책을 확인한다.
[ ] 관리자 계정에 Chrome 기기 관리 권한이 있는지 확인한다.

파워워시는 로컬 프로필과 동기화되지 않은 기기 내 데이터를 삭제합니다. 다운로드 폴더 파일, 로컬에만 저장된 사진, 저장된 네트워크 등의 데이터는 사라질 수 있습니다. Google 계정에 동기화된 데이터와 Google Drive 자료는 일반적으로 계정에 남지만, 동기화가 완료되지 않은 로컬 자료는 복구되지 않을 수 있으므로 백업을 먼저 확인합니다.

============================================================
4. 관리 콘솔에서 파워워시 정책 허용하기
============================================================

이 절차는 학생이나 학교 사용자가 크롬북에서 직접 파워워시를 실행할 수 있도록 기기 정책을 허용하는 과정입니다. 관리자 계정 및 기기 정책 변경 권한이 필요합니다.

1) admin.google.com에 관리자 계정으로 로그인합니다.
2) 메뉴에서 '기기 > Chrome > 설정 > 기기 설정'으로 이동합니다.
3) 왼쪽 조직 트리에서 대상 크롬북이 속한 조직 단위(OU)를 선택합니다.
4) '파워워시' 설정을 찾습니다. 설정 검색창에서 '파워워시'를 검색해도 됩니다.
5) '파워워시가 트리거되도록 허용'을 선택합니다.
6) '저장'을 클릭합니다.
7) 대상 기기가 인터넷에 연결되고 관리 서버와 정책 동기화가 되었는지 확인합니다.

정책 적용은 보통 몇 분 안에 시작되지만, 전체 반영에 최대 24시간이 걸릴 수 있습니다. 다른 OU의 정책을 바꾸지 않도록 대상 크롬북이 실제로 속한 OU를 먼저 확인합니다.

OU 정책 확인 요령:
- '상속됨'으로 표시되면 상위 조직 단위 설정을 따르는 상태일 수 있습니다.
- '로컬 적용' 또는 이에 해당하는 표시라면 해당 OU에서 별도 설정한 상태입니다.
- 상위 OU에서 허용해도 하위 OU가 별도 설정으로 덮어쓰는지 대상 OU에서 확인합니다.
- 여러 기기를 대상으로 일괄 변경할 때는 대상 OU와 적용 범위를 다시 확인합니다.

주의:
- 파워워시 정책은 사용자가 초기화를 실행할 수 있는지 제어합니다.
- 파워워시 허용은 기기 등록 해제나 학교 관리 해제를 뜻하지 않습니다.
- 파워워시를 허용해도 강제 재등록 정책이 켜져 있으면 초기화 후 학교 관리가 다시 적용됩니다.
- Google 공식 정책 안내에는 파워워시를 차단해도 허용된 TPM 펌웨어 업데이트가 아직 완료되지 않은 경우 데이터 삭제·초기화가 발생할 수 있는 예외가 안내되어 있습니다.

============================================================
5. 크롬북에서 직접 파워워시하기
============================================================

일반 크롬북에서 사용하는 기본 파워워시 절차:

1) 필요한 파일을 백업하고 크롬북에서 로그아웃합니다.
2) 키보드에서 Ctrl + Alt + Shift + R을 동시에 누릅니다.
3) 화면에 표시되는 '다시 시작'을 선택합니다.
4) 재시작 후 'Powerwash'를 선택합니다.
5) '계속'을 선택하고 초기화가 끝날 때까지 기다립니다.
6) 초기화 후 화면 지시에 따라 학교의 등록 절차를 진행합니다.

학교에서 강제 재등록을 사용 중이면 초기화 뒤 '이 기기는 학교에서 관리합니다'와 같은 관리/등록 화면이 나타날 수 있습니다. 이를 우회하려고 하지 말고 학교에서 지정한 등록 계정 또는 IT 담당자 절차를 따릅니다.

키보드 단축키가 작동하지 않거나 파워워시가 계속 차단된다면:
- 기기가 정책을 동기화했는지 확인합니다.
- 대상 OU의 파워워시 설정이 실제로 허용인지 다시 확인합니다.
- 학교 관리자에게 기기 상태와 정책 예외 여부를 확인합니다.
- 임의로 개발자 모드, 복구 모드 또는 비공식 우회 절차를 사용하지 않습니다. 강제 재등록과 보안 설정에 영향을 줄 수 있습니다.

============================================================
6. 관리 콘솔에서 원격 초기화하기
============================================================

관리 콘솔의 원격 재설정은 기기가 학교 관리 상태이고 관리자 권한이 있을 때 사용합니다.

1) admin.google.com에 관리자 계정으로 로그인합니다.
2) '기기 > Chrome > 기기'로 이동합니다.
3) 전체 기기 또는 대상 OU를 선택하고, 자산번호나 SN으로 기기를 찾습니다.
4) 대상 기기의 SN을 클릭해 기기 상세 화면을 엽니다.
5) '재설정(Reset)'을 선택합니다.
6) 목적에 맞는 옵션을 선택합니다.
   - 사용자 프로필 삭제(Clear User Profiles): 사용자 프로필 및 사용자 데이터를 삭제하되, 기기 등록 상태와 일부 기기 데이터를 유지하는 용도입니다.
   - 공장 초기화(Factory Reset): 로컬 데이터와 사용자 프로필을 지우고 기기를 공장 상태로 초기화합니다.
7) 데이터 삭제가 되돌릴 수 없다는 확인을 체크하고 재설정을 실행합니다.
8) 기기가 온라인 상태가 되어 명령을 수신했는지 확인합니다.

원격 재설정 명령은 기기가 네트워크에 연결되어야 처리될 수 있습니다. 기기가 오프라인이면 명령이 대기 상태로 남을 수 있습니다.

============================================================
7. 초기화 후 강제 재등록 정책
============================================================

학교에서 계속 사용할 크롬북은 일반적으로 초기화 후에도 학교 관리 상태를 유지해야 합니다. 이를 위해 관리 콘솔에서 강제 재등록 설정을 확인합니다.

경로:
기기 > Chrome > 설정 > 기기 설정 > 대상 OU > 등록 및 액세스(Enrollment and access) > 강제 재등록(Forced re-enrollment)

대표 옵션:
- 초기화 후 기기를 자동으로 강제 재등록: 지원되는 ChromeOS 기기가 초기화 후 자동으로 학교 도메인에 재등록됩니다.
- 초기화 후 사용자 인증정보로 강제 재등록: 사용자가 학교 계정 정보로 수동 등록하도록 요구합니다.
- 초기화 후 강제 재등록 안 함: 기기를 학교 계정에 다시 등록하지 않고 사용할 수 있습니다.

양품화 시 기본 원칙:
- 학교에서 다시 사용할 기기라면, 특별한 사유가 없는 한 강제 재등록을 유지합니다.
- 강제 재등록은 파워워시 차단 해제와 별개의 설정입니다.
- 초기화 뒤 자동 재등록이 되지 않으면 네트워크 연결, 대상 OU, 기기 상태, 재등록 설정을 확인하고 안내 화면에서 수동 등록을 진행합니다.
- 일부 기기는 자동 재등록을 지원하지 않거나 수동 등록 화면을 표시할 수 있습니다.
- ChromeOS Flex는 ChromeOS 기기와 재등록 동작이 다를 수 있으므로 해당 기기 유형에 맞는 공식 문서를 확인합니다.

8. 양품화 후 점검 체크리스트
============================================================

[ ] 초기화가 완료되어 초기 설정 화면이 표시된다.
[ ] 학교 도메인 관리 또는 등록 화면이 정상적으로 나타난다.
[ ] 학교의 지정된 계정/절차로 등록이 완료된다.
[ ] 관리 콘솔에서 기기가 다시 등록됨/프로비저닝됨 상태인지 확인한다.
[ ] 기기가 의도한 학생용 또는 예비기기 OU에 배치되어 있다.
[ ] 정책이 동기화되었는지 확인한다.
[ ] 로그인 제한과 게스트 모드 설정이 적용되는지 확인한다.
[ ] Wi-Fi, 업데이트, 필수 앱 및 확장 프로그램이 정상 적용되는지 확인한다.
[ ] 카메라, 키보드, 터치패드, 화면, 스피커, 충전, 포트 등 하드웨어를 점검한다.
[ ] 자산번호와 SN, 처리 결과, 이상 여부를 학교의 자산/수리 기록에 남긴다.

============================================================
9. 학교 관리에서 완전히 제외해야 하는 경우
============================================================

기기를 학교에서 계속 관리할 예정이라면 파워워시만 진행하고 등록 상태를 유지하는 것이 보통입니다. 수리 반송, 폐기, 양도, 매각 등으로 기기를 학교 관리에서 영구히 제외해야 할 때는 파워워시 정책 변경과 별도로 '등록 해제(Deprovision)'를 검토합니다.

관리 콘솔 경로:
기기 > Chrome > 기기 > 대상 기기 선택 > 등록 해제(Deprovision)

등록 해제 과정에서 공장 초기화를 함께 선택할 수 있습니다. Google 공식 안내에 따르면 공장 초기화는 사용자 프로필, 기기 정책, 등록 데이터를 제거합니다. 등록 해제된 기기를 수리 후 다시 학교에서 쓰려면 사용 가능한 업그레이드/라이선스 조건을 확인하고 재등록 절차가 필요합니다.

다음 작업은 구분해야 합니다:
- 파워워시 허용: 사용자가 기기 로컬 초기화를 실행하도록 허용
- 원격 재설정: 관리자가 등록된 기기의 사용자 프로필 또는 공장 초기화 실행
- 등록 해제: 기기를 학교의 관리 도메인에서 제외
- 사용 중지(Disable): 분실·도난 등으로 사용을 막는 조치. 등록 해제와 목적이 다름

등록 해제는 관리 라이선스와 기기 관리 상태에 영향을 주므로, 학교의 자산 담당자 또는 Google Workspace 관리자 승인 절차에 따라 진행합니다.

============================================================
10. 첨부된 디벗 MDM 자료에서 확인한 내용
============================================================

첨부 「디벗 MDM(크롬-CEU).pdf」에는 다음 관리 항목이 안내되어 있습니다.
- 관리 콘솔 접속: admin.google.com
- 교사·학생 등 조직 단위 구성 및 조직별 정책 적용
- 사용자 계정 개별 추가 및 CSV 일괄 업데이트
- CEU 등록 기기의 프로비저닝 상태 확인 및 조직 단위별 관리
- Chrome 기기 목록에서 SN으로 기기를 찾아 재설정
- 기기 사용 중지
- 파워워시 키: Ctrl + Alt + Shift + 영문 R
- 앱을 Google Play 또는 Chrome 웹 스토어에서 추가하고 강제 설치/허용/차단
- 기기 자동 업데이트, 강제 재등록, 파워워시 허용, 분실 반환 안내
- 게스트 모드, 로그인 제한, 도메인 자동완성, URL 차단, 기기 사용 시간 제한

첨부 자료에는 파워워시 허용 메뉴 경로가 '기기 > Chrome > 설정 > 기기 설정'으로 안내되어 있습니다. 콘솔 UI는 변경될 수 있으므로, 메뉴명이 다르면 관리 콘솔의 설정 검색에서 '파워워시'를 검색합니다.

11. 빠른 작업 흐름
============================================================

학교에서 계속 사용할 기기의 일반 양품화:

대상 SN·OU 확인
  -> 데이터 백업 확인
  -> 대상 OU에서 파워워시 허용
  -> 기기 직접 파워워시 또는 관리 콘솔 원격 공장 초기화
  -> 초기 설정 및 학교 재등록
  -> 관리 콘솔 상태·OU·정책 확인
  -> 하드웨어 점검 및 처리 기록

학교 관리에서 영구히 제외할 기기:

대상 SN·자산 상태 확인
  -> 학교 내부 승인 및 라이선스 조건 확인
  -> 등록 해제 및 필요 시 공장 초기화
  -> 네트워크 연결 후 관리 상태 변경 확인
  -> 반납·폐기·양도 기록
